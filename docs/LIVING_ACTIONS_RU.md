# Living Actions («Живые действия») — интеграционная записка

Статус: **кандидат в отдельной ветке, не публичный выпуск**. Не путать с уже опубликованной cinematic на main.

## Что действительно реализовано сейчас

- Пять начальных команд над пустым миром: город, лес, вулкан, энергия и свободная идея. Созданные объекты становятся отдельными экземплярами в сохранении, с координатами и постоянными ID.
- Слоты меняются по реальным флагам и ресурсам текущего локального симулятора: город → купол → дракон → лучники / переговоры / укрытие → повреждения → восстановление / развитие. У леса появляются животные и расширение; у вулкана — лава, геотермия, остров и исследования; у энергии — накопитель, сеть, стабилизация и модернизация.
- Одна декларативная **ASSET_REGISTRY** в `cinematic/living-actions.mjs`: существующие изображения `city/forest/volcano/energy.webp` одновременно используются в сцене, контекстных кнопках и каталоге. Прозрачный купол, животные и другие значки состояния — дешёвые CSS/DOM-композиции, не отдельные WebGL-сцены.
- Существующий `cinematic/chain-engine.mjs` рассчитывает стоимость, последствия и журнал событий. `playFeature` не мутирует исходный мир при ошибке; с `requestId` повторный вызов идемпотентен (32 последних ID). Блокировка повторных синхронных нажатий есть и в интерфейсе. Сохранение мигрирует старые JSON-сессии.
- Прокрутка мышью и одним пальцем, выбор объектов, ближайшие действия в видимой области, отдельное локальное сохранение позиции камеры и выбора. Новое строительство использует координаты текущего участка. Каталог позволяет создавать дополнительные города и прочие объекты.
- После действия Джинн сворачивает длинное сообщение, оставляя построенный объект открытым, с кнопкой раскрытия полного текста. Для начального состояния сделаны детерминированно воспроизводимые изображения без нарисованного заранее вулкана (CPU-скрипт `scripts/make_barren_backdrops.py`).
- Модуль включён в версионный офлайн-кеш `sw.js`. Анимации купола/дракона отключаются при `prefers-reduced-motion`.

## Файлы и воспроизведение

`cinematic/main.mjs`: подключение UI, восстановление камерного контекста и клики.
`cinematic/living-actions.mjs`: чистая функция `getLivingActions(world,{selectedId,viewport})` и реестр картинок.
`cinematic/chain-engine.mjs`: атомарные локальные переходы, стоимость и события.
`cinematic/render-ui.mjs`: один набор изображений во всём мире и интерфейсе.
`test/living-actions.test.mjs`: негативные и детерминированные модульные тесты.
`test/living-browser.cjs`: настоящий Chrome/Chromium, полный сценарий, перезагрузка, скриншоты, мышь и эмуляция touch.

Запуск без платного API:

```sh
npm run test:cinematic
npm run test:world
npm run test:living:browser
```

Последняя команда сама поднимает локальный HTTP-сервер и сохраняет изображения в `work/living-browser/`. Для GitHub Actions задаётся `CI=1`, чтобы использовать установленный Chromium. Тест проверяет >85% **геометрически незакрытого прямоугольника нового города** и 100% игрового viewport. Это не экспертная оценка художественного качества.

## Что ещё блокирует общий публичный выпуск

1. **Сервер и Telegram:** текущие `playBuild/playFeature` работают в существующем **локальном cinematic-движке**. Это ещё не подтверждённая сервером операция и не общая D1-сессия браузера/Telegram. Интегрировать с [World Server #329](https://github.com/mpaykin1/World_server/pull/329), [#332](https://github.com/mpaykin1/World_server/pull/332) и клиентом [scratch #15](https://github.com/mpaykin1/scratch-chain-reaction/pull/15) после их ревью/согласования версий. Не создавайте независимый серверный симулятор взамен уже существующего.
2. **GLB/APNG:** значения `model` в реестре — подготовленные идентификаторы, **не подключённые 3D-превью**. У [World Server #336](https://github.com/mpaykin1/World_server/pull/336) реальные GLB пока draft и есть блокер независимой проверки бинарного diff. До его устранения остаются проверенные общие WebP/CSS-превью, а не несуществующие опубликованные 3D-модели.
3. **Практически бесконечная карта:** камера в этом шаге ограничена координатами ±100000; нет потоковой генерации чанков, строгого теста коллизий и пространственной модели идей. Согласовать с отдельными [scratch #18](https://github.com/mpaykin1/scratch-chain-reaction/pull/18) и [#22](https://github.com/mpaykin1/scratch-chain-reaction/pull/22), не подменяя их работой.
4. **Релизный gate:** после объединения серверного состояния необходимы серверные CAS/идемпотентность и негативный network QA, синхронный Telegram-journey, независимое «Пороки»-ревью, полный GitHub CI, реальные iPhone FPS/память и проверка опубликованного точного SHA. **Мобильная эмуляция не считается испытанием на физическом телефоне**; локальные скриншоты не означают доступность публичного URL.

При конфликте веток сохраняйте работу других агентов: импортируйте небольшие проверенные изменения через новый интеграционный PR.
