# Агенты «Цепной реакции» — общий протокол

Этот файл относится к `mpaykin1/scratch-chain-reaction`. `World_server` — отдельный репозиторий со своими правилами (`AGENTS.md`); изменения там оформляются отдельно и не обходят защиту `master`.

## Роли

- **@chatgpt** — архитектура, причинно-следственная логика, сценарии Джинна, документация, тестовые критерии и интеграция с World Server.
- **@qwen** — WebGL 2.0 / GLSL ES 3.0, мобильная производительность, эффекты, шейдеры и тесты видеорендеринга.
- Обоим агентам разрешено находить дефекты чужого кода, предлагать контрпримеры и проводить независимое ревью; ответственность за конкретную задачу определяется `TASKS.md`.
- `@qwen` здесь означает **назначение задачи, а не действующее подключение к API**. GitHub Actions сам по себе не запускает модели; для этого требуется отдельный, явно настроенный runner/API.

## Перед началом каждого задания

1. Прочитать `AGENTS.md`, `TASKS.md`, `DECISIONS.md`, `CONTEXT.md`, актуальный `main` и связанную реализацию. Проверить реальный SHA и незаконченные PR.
2. Взять свою `TODO`-задачу. Перевести её в `IN_PROGRESS` только на своей ветке `ai/chatgpt/<id>-<topic>` либо `ai/qwen/<id>-<topic>`. Не выдавать задачу за эксклюзивно захваченную, пока ветка/PR не опубликованы; перед началом проверить конкурирующие PR по тому же ID.
3. Сделать минимальное изменение, воспроизвести дефект, добавить регрессионный тест и запустить подходящие проверки. Не трогать посторонний dirty worktree; не смешивать независимые задачи в одном PR.
4. Записать обоснование архитектурного решения в `DECISIONS.md`, если меняется архитектура. Обновить задачу и запустить `node scripts/sync-agent-context.mjs`.
5. Создать PR в `main` с SHA, точными проверками и ограничениями. `IN_REVIEW` означает, что код предложен, но ещё не принят. `DONE` — только после merge и подтверждённых тестов. **Никаких прямых push в `main` и автоматического merge.**

## Реальная архитектура на момент создания протокола

- `cinematic/chain-engine.mjs`: чистый детерминированный движок. `getGenieChoices()` даёт четыре варианта, `playCustomDecision()` — пятое, введённое игроком решение. Не подменять критический игровой цикл недетерминированными ответами LLM.
- `cinematic/render-effects.mjs`: WebGL 2.0 **слой визуальных эффектов поверх 2D-графики** с CSS fallback; это пока не полный 3D-рендерер. Текущий GLSL использует uniform `ecology` (не выдумывать `uEcology`).
- `cinematic/quality.mjs` ограничивает фактический буфер 1080 px по длинной стороне и DPR максимум 2; `cinematic/adaptive-quality.mjs` меняет качество по нагрузке. 60 FPS — цель для измерения на устройстве, **не подтверждённая гарантия**.
- Сохранять отсутствие обязательной авторизации в текущем демо, обработку отключённого WebGL, `prefers-reduced-motion`, офлайн-режим и существующий Scratch/TurboWarp player.

## Контракт качества

- Для эффекта Qwen: `#version 300 es`, явный `layout(location=0)` для новых вершинных атрибутов, корректный precision, без `inverse()` или умножения матриц во фрагментном шейдере; не переносить без нужды операции на GPU.
- Для мобильного рендера: физическая длинная сторона буфера ≤1080 px, DPR ≤2, управляемый бюджет частиц ≤1000, корректная потеря/восстановление WebGL-контекста.
- Размер нового JS-модуля ≤400 строк, новая функция ≤50 строк и ≤10 импортов. Исключения — только с явным обоснованием в PR.
- Проверки: `npm run test:cinematic`; `npm run test:cinematic:browser` после локального HTTP-сервера и установки Playwright; `npm run test:agents`. Недоступные проверки перечислять отдельно, не писать PASS без запуска.
- Публичную игровую ссылку выдавать как *проверенную* только при опубликованном точном SHA, реальных desktop/mobile браузерных проверках и покрытии игровой сцены на проверяемых устройствах >85%; до этого ссылка не означает готовность выпуска.

## Доска и передача между агентами

`TASKS.md` — источник статуса: `TODO → IN_PROGRESS → IN_REVIEW → DONE`; `BLOCKED` — отдельное состояние с описанием зависимости. `DECISIONS.md` хранит мотивировку. `CONTEXT.md` содержит человеческий паспорт и автоматически формируемую сводку. Скрипт `scripts/sync-agent-context.mjs` идемпотентен; CI отклоняет несогласованное состояние. Workflow обновляет `CONTEXT.md` в опубликованных `ai/**`-ветках без прямого push в `main`.

Ни один из агентов не копирует секреты в код или логи. В будущем для настоящего автоматического вызова Qwen использовать GitHub Actions Secrets (например, `QWEN_API_KEY`), ограниченные разрешения, тайм-аут, лимит расходов и ручной запуск до проверки безопасности. Для конфликта версий — обновить ветку и пересчитать тесты, а не force-push чужие изменения.
