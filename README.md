# Цепная реакция — анимированная Scratch 3

Полностью самостоятельный проект Scratch 3 с реальными PNG/SVG-костюмами, **не картинка и не HTML-имитация**. Запускается в официальном Scratch через импорт `.sb3`, а на GitHub Pages через совместимый проигрыватель TurboWarp.

## Собственный проигрыватель TurboWarp (без внешнего iframe)

В `player/` находится наш HTML/JS-интерфейс на основе открытого
[TurboWarp Scaffolding](https://github.com/TurboWarp/scaffolding) 0.4.0,
лицензия MPL-2.0. Это самостоятельный *проигрыватель*, не полная копия редактора
TurboWarp или TurboWarp Packager.

- `player/index.html` — собственный игровой экран с PWA, зелёным флажком при
  старте, перезапуском, полноэкранной кнопкой и подсказкой для iPhone.
- `player/player.js` — загружает `chain-reaction-animated.sb3` непосредственно
  с наших GitHub Pages. На телефоне подгружается отдельная
  `player/chain-reaction-portrait.sb3` с исходными скриптами и адаптированными
  координатами пяти Scratch-кнопок.
- `scripts/build_portrait_sb3.py` — автоматически создаёт портретную сцену
  из оригинального Scratch-архива и нашего `world_portrait.webp`.
- `.github/workflows/self-host-player.yml` — скачивает строго закреплённую версию
  движка из npm, кладёт JS и лицензию MPL-2.0 в `player/vendor/`, тестирует
  сам игровой canvas на iPhone, в горизонтальном режиме и на десктопе.
  Только после прохождения тестов на main публикует собранный движок и .sb3.
- `test_selfhost_player.mjs` — проверяет запуск реального Scratch,
  отсутствие запросов к turbowarp.org/CDN, пять видимых кнопок, ход игры
  после нажатия и минимум 85% занимаемой игровой сценой площади iPhone.

Для локальной сборки: `npm install`,
`python -m pip install Pillow==11.3.0`,
`python scripts/build_portrait_sb3.py`, затем скопировать
`node_modules/@turbowarp/scaffolding/dist/scaffolding-with-music.js` и
`node_modules/@turbowarp/scaffolding/LICENSE` в `player/vendor/`.
Для локального теста: `python -m http.server 4173` и
`npx playwright install chromium && npm run test:player`.

Важно: сам браузер Safari не разрешает скрыть свою оболочку из обычной
вкладки. Для этого установи веб-приложение через «На экран Домой».
Программа `player/` не предоставляет 3D-рендерер сама по себе:
3D-модели/GLB потребуют отдельного рендерера либо совместимых Scratch-расширений.

## Системный режим: события и последствия

В меню основной игры добавлен экспериментальный режим `cinematic/reactive.html`.
Он использует `world-engine.mjs` (чистая воспроизводимая симуляция)
и `game-ui.mjs` (интерфейс). Основная игра с WebGL-эффектами, звуком,
офлайн-режимом, улучшенной доступностью и самостоятельным Scratch-файлом
сохранена без замены движка.

- Строительство имеет стоимость, срок завершения и регулярное влияние на ресурсы.
- Кризисы имеют отдельные пороги начала и восстановления; их последствия
  не накапливаются бесконечно в темпах потребления.
- Есть очередь задержанных событий, история причин и автоматическое
  восстановление сохранённой игровой сессии.
- Команды «прилетел дракон» → «люди в него стреляют» → ответный удар
  исполняются в одном и том же мире.
- Серверный ИИ пока не подключён; неизвестная идея требует уточнения.
  Для будущего ИИ предусмотрен белый список допустимых команд.

Проверки: `npm run test:world`, а при запущенном локальном сервере —
`npm run test:world-ui`. Публикация системного режима требует
прохождения реального браузерного теста с покрытием экрана >85%.

## Кинематографичный браузерный режим: локальная симуляция и эффекты

Браузерная игра `cinematic/` дополняет, **но не заменяет** настоящий Scratch-проект и собственный TurboWarp-проигрыватель.

- `cinematic/chain-engine.mjs`: детерминированный движок с причинными событиями, ограничениями ресурсов, отложенными последствиями и безопасным восстановлением сохранений. Распознаются город, лес, энергетика, вулкан, фермы, орошение и очистка воды. Нераспознанная идея **не изменяет мир**, а возвращается на уточнение. Это локальные правила, не подключённая LLM.
- `cinematic/render-effects.mjs` и `quality.mjs`: независимая WebGL2-визуализация волн последствий с GLSL ES 3.0. Физический буфер ограничен 1080 пикселями по длинной стороне **после DPR**; при перегрузке качество снижается. Если WebGL2 недоступен или включено снижение анимации, сохраняется исходная CSS-графика.
- `cinematic/ambient-audio.mjs`: звук по действию пользователя, по умолчанию выключен; высота фона отражает состояние ресурсов.
- `sw.js`: локальный PWA-кеш игры и рисунков для работы без сети после первого успешного открытия. HTML при наличии сети проверяется заново, чтобы исправления доходили до игроков. Автосохранение браузерного режима хранится локально, без аккаунта.
- `.github/workflows/cinematic-quality.yml`: тесты движка, полный игровой цикл в трёх размерах окна, проверка покрытия экрана более 85%, WebGL, звука, offline reload и совпадения опубликованных файлов.

Команды: `npm run test:cinematic`; для браузерных тестов дополнительно запусти локальный HTTP-сервер на порту 8765 и `npm run test:cinematic:browser`. Площадь игровой сцены и лимит буфера проверены в автоматизированном Chromium; это **не** гарантия 60 FPS или проверка на физическом iPhone 11. Для запуска iOS PWA без панели Safari действие «Поделиться → На экран Домой» всё ещё требуется самой iOS.

## Что сделано

- Старт: только сухая пустошь, **без вулкана**, по ней бредут люди.
- 5 игровых вариантов: город, лес, энергия, вулкан и собственная идея.
- Злой Джинн вылезает из диалогового окна, имеет 4 анимационных кадра.
- Движутся человечки, пыль, дым, вулканические частицы и лопасти ветряков.
- После каждого хода видны новые объекты, динамические показатели ресурсов и последствия.
- Джинн предлагает 4 компромиссных решения и пятый свободный ответ.
- Ресурсная модель с накоплением дефицита: электричество, вода, пища, экология, бюджет и население. После кризиса можно продолжать игру.
- Нет серверных API, токенов, платных зависимостей; для генерации файла достаточно Python 3 + Pillow, если исходные арты уже извлечены.

## Исходный код и редактирование

1. `python extract_assets.py` — извлечёт отдельные PNG-ассеты из `chain-reaction.sb3` в `assets/`.
2. `python build_animated.py` — соберёт новый `chain-reaction-animated.sb3` с исходными анимациями и игровыми скриптами.
3. `python test_release.py` — запустит статические проверки структуры и комплектности.

`asset_prep.py` — дополнительный исходный пайплайн обработки изображений, если доступны исходные широкоформатные арты, созданные для проекта. Для штатной пересборки исходные изображения не требуются: они уже включены в `.sb3`.

Важное уточнение: свободный текст обрабатывает встроенная детерминированная модель Scratch по распознаваемым ключевым словам, **это не подключённая LLM**. Никаких тайных API-вызовов или облачных расходов нет.
